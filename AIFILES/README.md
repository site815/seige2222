# Scenario colony AI

These editable definitions control the simple local AI colonies and the center colony in observer mode. `Rules` remains the authority for construction costs, staffing, production, deliveries, repairs, and alien threats.

- [colony_ai.json](colony_ai.json) sets the decision interval, ordered building targets, placement search, sensor extension, and bounded setup action/time limits. Repeated targets may raise earlier counts. `target_policy` requires completion and staffing in order, so later industry cannot exhaust the supplies needed for its prerequisites. Current priorities establish service capacity, four turrets and four perimeter sensors before extraction.
- [developed_start.json](developed_start.json) supplies finite core inventory and population for the developed scenario option. Setup runs the actual simulation until required buildings finish within `developed_setup_seconds` and the action limit. Couriers, builders, services, upkeep, production and threats all apply. Preparation time and manufactured output are real, not preset awards.

A starting AI uses the ordinary scenario start. Both types then use the same controller: choose nearby matching deposits, extend live coverage when required, establish production and defenses, and rebuild missing target buildings when affordable. Orders use the normal simulation commands. Robots, inputs, maintenance, delivery time, and attacks retain their normal effects. The controller waits for sensor workers rather than repeatedly buying unstaffed masts.

This is a deterministic construction controller, not a strategic opponent with diplomacy, raids, fleets, or trade. Colonies have independent local inventories and threats; neighboring cells do not transfer goods or attack one another. The developed seed is a scenario choice, not recurring AI income.

The verified v0.7 package adds independent scenario switches for background bugs and periodic attacks, both ON by default. The scenario passes them to `FSeigeScenarioAI::Initialize` before developed preparation begins; every local AI uses the same choices as the center. Disabling either source affects its actual simulation spawning during preparation and play. It does not grant resources, skip construction, or change the AI plan. The optional trailing initialization parameters preserve the previous behavior for existing callers. Decision timing derives from saved simulation time and current state. Initialize with `bDeveloped=false` and then load the colony snapshot to resume, avoiding redundant preparation. The scenario save must also preserve and validate `GetConfigFingerprint()`; changing either AI JSON file changes that fingerprint. No independent hidden AI timer or random state needs serialization.

Reload definitions by starting a new scenario. Runtime validation rejects bad versions, missing files, invalid numerical ranges, unknown building/resource references, overflowing seed inventory, and a developed layout that cannot be established. AI plans refer to existing building definitions; new simulation capabilities still require engine work.
