# Shared seasonal weather

`Tools/import_weather_v09.py` creates the original shared snow parameter collection and flake material, then adds a snow-colour wrapper to the currently referenced project scenery material masters. Imports completed successfully for ten masters and the stable ambient cubemap; `import_report.json` records the exact assets. The three calendar/solar native tests passed. Editor WorldReview5 completed 38 stages with zero assertion failures; its dawn, night and winter captures were inspected. Final packaged acceptance and isolated performance measurement remain pending.

The wrapper preserves existing photographic textures, opacity masks, normals and roughness. Snow retains some underlying colour variation; terrain coverage is reduced on steep faces. Vegetation uses an authored coverage fraction. This is a first seasonal material treatment, not simulated snow depth, branch accumulation, ice or a claim of photoreal snow. Existing texture and source-mesh licenses remain unchanged; see the corresponding environment asset records. The ambient cubemap is Epic's bundled `/Engine/MapTemplates/Sky/DaylightAmbientCubemap`, copied to `/Game/Art/WeatherV09/T_AmbientDaylight` for cooking. It remains Unreal Engine content under its existing license; no private reference photographs are copied.

The raw copied `Content/Art/WeatherV09/T_AmbientDaylight.uasset` is excluded from public Git. A fresh source checkout regenerates it from the developer's licensed Unreal Engine installation: `build.ps1` automatically runs `Tools/prepare_engine_assets.py` when the file is absent, after the Editor compile and before cooking. That minimal commandlet copies only the cubemap; it does not reauthor seasonal materials. For manual setup before editor play or asset validation, run the same script with the project's Unreal Editor Python commandlet. The full `Tools/import_weather_v09.py` remains the material-authoring path and should run after terrain and foliage material importers. Both load `/Engine/MapTemplates/Sky/DaylightAmbientCubemap` and save the configured local copy. Keep the generated local file for cooking; it is not CC0 or original project artwork. See the [Unreal Engine license](https://www.unrealengine.com/eula/unreal) for distribution terms. The game credits retain Epic's prescribed product notices.

`Rules/calendar.json` owns daylight/night lengths, season length and initial phase. `Graphics/weather.json` owns appearance and performance bounds. One scenario clock drives every colony regardless of its AI preparation age. Solar generation uses the actual daylight interval; winter has no unapproved yield, mobility or solar penalty.

Lighting intensity/tint changes continuously. Sun-shadow direction changes only after the configured angular threshold and minimum cadence; a dark night light is not rotated. The skylight uses the authored ambient cubemap and changes intensity/tint rather than capturing the live sky. This avoids a first-load failure where deferred shader compilation allowed the only scene capture to occur after dawn switched the sun off. The first stable-cubemap capture remained too dark at dawn/night. The next authored calibration adds 2 EV only in the dark phase and keeps half the daytime sky intensity; both fade to the unchanged midday settings. It adds no fill lights, fog, automatic exposure metering or solar power. The following Editor review confirmed readable terrain/trees/shuttle at dawn and night, with a cool night tint. Midwinter visibly covers terrain and trees; this remains a colour treatment, not snow-depth simulation. The snowflake master explicitly supports instanced meshes. Falling snow uses one bounded instanced component, follows interpolated calendar presentation, and pauses with the game. It does not create one actor per flake or rebuild/reseed terrain.

Regenerating an older terrain/foliage master can remove the seasonal wrapper. Run this importer after those material importers; its marker makes unchanged masters idempotent. Inspect near/far grass, trees, rock faces and terrain together before accepting the winter result, and measure moving-light/snow cost at the same camera and resolution as summer.
