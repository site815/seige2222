# Calendar-driven foliage wind

The current v0.10.6 foliage pass uses the GPU materials already assigned to the retained trees, canopy proxies, meadow cards and wildflowers. It changes no source mesh, photographic texture, color, normal, opacity mask or seasonal snow connection. Bark/trunks remain rigid; the visible canopy bends and rustles through leaf-material world-position offset. Crown bend grows with normalized mesh height instead of translating almost the entire canopy equally. Matching source/proxy bounds and world-space phase keep their motion coherent across the existing representation change.

`SeigeWeather.cpp` publishes one bounded wind phase and its previous-frame value through `MPC_Weather` each rendered frame. The visual clock integrates actual calendar advance including the fixed-step remainder. Cosmetic speed follows the square root of time-lapse speed, capped at an editable 4×: 1× simulation gives 1× wind, 10× gives about 3.16×, and 20× gives 4×. The colony/calendar rates remain unchanged. This avoids turning fine leaf motion into a mechanical high-frequency vibration. Phase stays continuous across speed changes and freezes on pause. Shader oscillations use only the first three integer harmonics, so cycle wrapping remains continuous during long sessions. `PreviousFrameSwitch` supplies the preceding pose for temporal motion vectors; loading/seeking the calendar resets both poses together.

Editable controls are in `Graphics/weather.json`: cycle duration, maximum cosmetic playback rate, canopy sway, fine leaf rustle, grass sway, fine tree-detail range and distance-fade start fraction. Defaults are a 12-second base cycle, 14 cm crown sway, 1.8 cm flutter and 4 cm grass sway. Fine leaf flutter fades between 156 and 260 m, while broad crown motion remains active on every visible tree/proxy at survey zoom. The existing `Graphics/scene.json` grass range stays authoritative: grass fades between 36 and 60 m and retains its per-instance WPO cutoff. A distant tree can become too small for sub-pixel motion to be obvious, but it no longer stops moving at a fixed camera-distance boundary.

The highest allowed settings fit within each material's declared maximum WPO displacement: 48 cm for foliage and 16 cm for grass. Unreal extends culling bounds accordingly. Whole tree transforms are never ticked. Shadows retain the existing rigid cache policy; individual leaves do not force forest shadow pages to redraw every frame. This deliberately omits tiny leaf-shadow animation for performance.

Run `Tools/import_foliage_wind.py` after rebuilding source scenery/grass materials. It modifies only the targeted material masters and adds parameters to the existing weather collection, validates every graph link and unchanged surface input, checks shader compile errors, and writes `wind_import_report.json`. Use a D3D12 commandlet with `-AllowCommandletRendering -RenderOffscreen`, then verify the actual built game. A NullRHI import alone does not establish shader correctness or visual performance.

The native `Seige.Presentation.WindClock` test checks phase slopes, pause retention, wrap continuity and long-session precision. `Seige.Presentation.WindTimelapse` checks 1×/10×/20× cosmetic rates, 30/120 FPS agreement, pause and speed-switch continuity. Configuration validation includes eight negative wind cases. These do not substitute for rendered checks.

For rendered source/proxy review use `-GraphicsBenchmark -BenchmarkView=hills -BenchmarkWindPoses -BenchmarkZoom=1600` and again at `-BenchmarkZoom=7000`, with distinct `-BenchmarkName` values. Each run samples ordinary 10× play, then pauses the world and captures phases 0 and π/2 after a 0.75-second temporal-AA settle. It writes `hills.png` and `hills-wind-phase1.png`, checks all tree instance batches retain WPO with no distance cutoff, and records proxy batch counts. The calendar/sun and camera stay fixed between poses; cloud/atmosphere shaders and render-history noise can still change some background pixels, so full-image difference alone does not prove crown movement. `-BenchmarkNoWind` now disables both tree and grass WPO for a separate timing comparison; do not combine it with the pose test. Shader import recorded 277 vertex instructions for tree masters (previously 221); expanded visible wind range has a cost and no performance improvement is claimed without an isolated comparison.

The v0.10.6 Editor phase-pair review is archived in [v0106-wind-review/review.json](v0106-wind-review/review.json), alongside both near/survey reports and four inspected screenshots. Both runs checked 576 tree batches, including 288 proxy batches, with zero distance-disabled crown batches. Crown-region pixels changed substantially more than open-ground controls at both zooms. The record includes imported material hashes and the reviewed executable/source identities. These captures establish visible distant crown motion; they do not establish final Shipping acceptance, a minimum frame rate, or completion of separate terrain work.
